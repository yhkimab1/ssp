# 정부지원사업 매칭·AI 사업계획서 서비스 구현 지침서

## 1. 작업 목적과 진행 원칙

기존 사이트를 실제 기업이 지원사업을 찾고, 신청자격을 확인하고, 보유 자료를 활용해 공고별 지정양식 사업계획서를 작성하는 서비스로 발전시킨다.

- 기존 프로젝트의 코드, 실행 방법, 저장소 지침, 데이터 구조와 구현 상태를 먼저 확인한다. 기존 기술 구성을 우선 활용한다.
- 아래 단계 순서로 구현한다. 각 단계의 완료 기준을 검증한 후 다음 단계로 진행한다.
- 기존 기능을 불필요하게 재작성하지 않는다. 이미 구현된 요구사항은 검증하고 부족한 부분만 보완한다.
- 외부 서비스 키나 계정이 없으면 연결 지점을 구현하고 필요한 설정을 문서화한다. 샘플 응답을 실제 OCR·AI·수집 결과처럼 표시하지 않는다.
- 실제 결제, 운영 배포, 유료 서비스 가입은 별도 승인 없이 진행하지 않는다.
- 각 단계 완료 시 변경 내용, 검증 결과, 남은 외부 설정 및 제한사항을 기록한다.

## 2. 기존 화면에서 확인한 기준 상태

검토 경로: `/programs/1`, `/programs/1/plan`, `/upload`.

- 공고는 샘플 데이터로 안내되어 있다.
- 등록증 업로드는 실제 인식 대신 예시 값을 채운다고 안내되어 있다.
- 상세 화면에는 일반 지원 대상과 수동 서류 체크리스트가 있다.
- 계획서 화면은 기업정보를 입력받아 공통 형식의 초안을 만들고 TXT 다운로드를 제공한다.
- 빈 입력으로 생성한 초안에도 확인되지 않은 긍정적 기업 설명이 포함되어 있다.
- 융자사업에 지원금이라는 표현이 사용된다.
- 좁은 화면에서는 긴 설명으로 핵심 정보가 아래로 밀리고, 계획서 안내에 ‘왼쪽’이라는 표현이 남아 있다.

이 관찰은 검토 당시 화면 기준이다. 회원·저장·권한·백엔드 구현 여부는 코드를 확인해 판단한다.

## 3. 목표 사용자 흐름

비회원 검색·공고 조회·추천 체험 → 등록증 분석 및 정보 확인 → 맞춤 공고 추천 → 자격 근거 확인 → 로그인 및 기업정보 저장 → 회사 자료 등록 → 부족한 정보 보완 → 공고별 지정양식 초안 작성 → 증빙 점검 → 공식 신청 사이트 이동.

검색과 공고 열람에 가입을 강제하지 않는다. 기업정보 저장 또는 계획서 작성 시 가입을 유도하고, 가입 전 입력 내용은 안전하게 이어받는다. 이미 로그인한 사용자는 저장된 기업정보를 재사용한다.

## 4. 1단계 — 기반 구조와 데이터 모델 [P0]

### 구현

- 프로젝트 실행·검증 방법과 기존 데이터 흐름을 파악한다.
- 사용자, 기업, 기업별 회원 권한, 기업 프로필, 업로드 자료, 추출 사실, 공고, 공고 버전, 자격 규칙, 양식, 계획서 버전, 증빙 상태, 관심사업, 수집 출처·실행 이력을 모델링한다.
- 모든 기업자료와 문서에 기업 식별자를 연결한다. 다중기업 관리가 가능하도록 처음부터 설계한다.
- 추출 사실은 값, 출처 파일/URL, 페이지 또는 본문 위치, 추출일, 기준일, 사용자 확인 여부를 기록한다.
- 공고 원문·첨부파일·정정 이력과 구조화된 필드를 연결한다.
- 샘플 데이터와 실제 데이터를 명확하게 분리한다.

### 완료 기준

- 현재 기능을 유지하면서 기업별 데이터 분리와 공고 버전 관리가 가능하다.
- 필요한 환경변수와 실행·마이그레이션 방법이 문서화되어 있다. 비밀값은 저장소에 넣지 않는다.

## 5. 2단계 — 회원·기업·파일 관리 [P0]

### 구현

- 회원가입, 로그인, 로그아웃, 탈퇴 및 세션 관리. 간편 로그인은 사용 가능한 공급자부터 연결한다.
- 비회원은 검색·상세 조회·추천 체험, 회원은 기업정보 저장·계획서 작성·자료 재사용이 가능하도록 한다.
- 가입 후 기존 체험 데이터를 해당 사용자 기업에 안전하게 연결한다.
- 기업 추가·선택·전환을 제공하고 현재 작업 중인 기업을 항상 표시한다.
- 기업별 자료함, 파일 삭제, 자료 교체와 보관 정책을 제공한다.
- 서버에서 기업별 접근 권한을 검증한다. 다른 기업의 파일 주소나 문서 ID만으로 접근할 수 없도록 한다.
- 업로드 목적, 지원 형식, 크기 제한, 보관·삭제 기준을 안내한다. 비회원 임시 파일은 만료 후 삭제한다.
- 파일 확장자뿐 아니라 실제 형식을 검증하고, 파일 처리 실패와 악성 파일에 대한 방어를 마련한다.
- 사업자등록증에는 대표자 성명·생년월일·주소 등 개인정보가 포함된다. 원본 파일은 OCR 후 즉시 삭제하고 추출 텍스트만 저장하는 것을 기본으로 하며, 원본 보관이 필요하면 수집 동의·보관 기간·암호화를 명시하고 개인정보처리방침을 제공한다.

### 완료 기준

- 로그인 후 기업정보와 문서가 복원된다.
- 다른 회원·기업의 파일과 문서에 대한 접근 차단을 검증한다.
- 기업 전환 시 자료·추천·문서가 섞이지 않는다.

## 6. 3단계 — 실제 OCR와 기업정보 재사용 [P0]

### 구현

- 사업자등록증 JPG·PNG·PDF에서 상호, 사업자번호, 대표자, 개업일, 주소, 업태, 종목을 추출한다.
- 낮은 신뢰도·누락 항목을 강조하고 사용자가 확인·수정한 뒤 저장하도록 한다.
- 등록증으로 확인할 수 없는 매출, 직원 수, 체납, 보유 인증 등은 별도로 입력받고 기준일을 기록한다.
- 저장된 기업정보를 추천·자격검증·계획서에 자동으로 연결한다.
- 단순 업종 문구를 공식 업종 코드로 임의 확정하지 않는다. 해석이 불확실하면 사용자 확인을 요청한다.

### 완료 기준

- 실제 파일을 분석하고 예시 값으로 대체하지 않는다.
- 인식 실패·일부 누락·사용자 수정 흐름이 정상 동작한다.
- 이미 저장한 항목을 계획서에서 다시 입력할 필요가 없다.

## 7. 4단계 — 회사 자료·판매 사이트 분석 [P0]

### 입력 방식

다음 중 하나 이상을 선택적으로 제공하게 한다. 모든 자료를 필수로 요구하지 않는다.

- 회사소개서·제품소개서·기존 사업계획서·제안서 파일.
- 홈페이지·쇼핑몰·상품 상세페이지 URL.
- 인증서·특허·실적 자료 및 관련 이미지.
- 파일이나 사이트가 없을 경우 직접 설명.

### 구현

- PDF·DOCX·PPTX·HWPX·이미지 등 실제 처리 가능한 형식을 명시한다. HWP 등 추가 형식은 변환 가능성을 확인하고 미지원 시 대체 업로드 방법을 안내한다.
- 기업 개요, 제품·서비스, 고객, 가격, 판매 채널, 보유 역량, 실적, 인증·특허 정보를 추출한다.
- 추출 결과를 기업 프로필 후보로 보여주고 사용자가 채택·수정하게 한다.
- 파일·페이지·URL 단위로 근거를 유지한다. 자료의 작성 시점과 매출 등 사실의 기준 시점을 구분한다.
- 기존 정보와 충돌하면 덮어쓰지 말고 차이를 표시한다. 새로운 자료 업로드 시 변경분만 재확인한다.
- 공개 URL만 허용하고 로그인·접근 제한을 우회하지 않는다. URL 수집은 내부망·메타데이터 주소 접근 및 리다이렉트 우회를 차단한다.
- URL을 읽을 수 없으면 PDF·화면 캡처·본문 붙여넣기를 제공한다.
- 자료와 웹페이지의 문장을 AI에 대한 지시로 실행하지 않는다. 자료는 분석 대상 데이터로만 처리한다.
- ‘업계 최고’, ‘고객 만족 1위’ 등의 광고 표현을 검증된 사실로 채택하지 않는다.
- 수치·실적을 추정하거나 만들어내지 않는다. 사용자 진술과 증빙 확인 사실을 구분한다.
- 신청 목적·목표·예산·실행 일정처럼 자료에 없는 항목만 추가 질문한다.
- 기업별 자료함에 저장하고 다른 공고 작성에도 재사용한다. 삭제된 자료가 이후 생성에 계속 참조되지 않도록 파생 데이터 처리 기준을 정한다.

### 완료 기준

- 회사소개서 또는 상품 URL에서 추출한 사실을 사용자 확인 후 초안에 활용할 수 있다.
- 주요 사실의 원문 출처를 다시 열 수 있다.
- 자료가 없어도 직접 입력으로 작성할 수 있다.
- 오래된 정보·충돌·접근 실패·광고 문구를 처리하는 흐름을 검증한다.

## 8. 5단계 — 실제 공고 및 지역기관·대학 수집 [P1, 기반 작업과 병행]

### 수집 대상

- 시청·군청·구청·광역시·자치도.
- 경제통상진흥원·경제진흥원·테크노파크·디자인센터.
- 문화·관광재단, 지역 산업진흥기관, 창조경제혁신센터, 상공회의소.
- 대학 본부·산학협력단·창업지원단·창업보육센터.
- RISE·지역혁신·앵커사업 등 별도 사업단 홈페이지와 게시판.

### 구현 순서

1. 기관·지역·게시판 URL·수집 방식·갱신 주기·담당 상태를 관리하는 출처 목록을 만든다.
2. 공식 API·제공 데이터를 우선 연결하고, 공개 게시판은 접근 정책에 맞춰 수집한다.
3. 초기 검증 지역을 정하고 해당 지역 기관·대학의 별도 게시판까지 수집한다. 지역 미지정 시 설정 가능하게 구현하고 전체 수집을 완료했다고 표시하지 않는다.
4. 본문과 PDF·HWP·HWPX·DOCX·이미지 첨부를 분석한다. 미지원·실패 첨부는 검수 대상으로 남긴다.
5. 지원 대상, 지역, 업종, 업력, 지원 방식, 금액, 접수기간, 제출서류, 지정양식, 신청 URL을 표준화한다.
6. 같은 사업의 재게시·정정·차수별 모집을 구분하고 중복을 통합한다. 별개 모집 차수는 무조건 병합하지 않는다.
7. 연장·취소·예산 소진·조기 마감·양식 변경을 감지하고 버전을 보존한다.
8. 수집 실패·구조 변경·분석 실패·장기 미갱신 출처를 보여주는 운영 화면과 재수집·수동 수정 기능을 제공한다.
9. 검증된 출처를 지역별로 확대한다.

### 완료 기준

- 각 공고에 공식 원문·첨부·최종 확인일·접수 상태가 표시된다.
- 첨부파일에만 있는 조건을 근거와 함께 확인할 수 있다.
- 대표 출처에서 최초 수집·중복·정정·실패 복구를 검증한다.
- 실제 확보한 범위와 실패 상태를 관리하며 ‘전국 100% 수집’을 근거 없이 표시하지 않는다.

## 9. 6단계 — 근거 기반 추천·신청자격 검증 [P0]

### 구현

- 추천 이유와 신청자격 판단을 구분한다. 높은 추천 점수를 신청 가능 확정으로 표시하지 않는다.
- 조건별 `충족 / 미충족 / 확인 필요`와 기업정보, 공고 근거·페이지, 판단 기준일을 표시한다.
- 지역·업력·업종·기업 규모·매출·인력·제외 조건 등을 검증한다.
- 본점/사업장 소재지, 신청 시점/공고 시점 등 조건의 기준을 공고에 맞춰 처리한다.
- 정보가 없거나 조건이 모호하면 추가 질문 또는 검수 상태로 남긴다.
- 보조금·융자·보증·교육·컨설팅을 구분하고 금액·상환·자부담 등의 표시 항목을 맞춘다.

### 완료 기준

- 각 판단을 원문과 기업정보로 설명할 수 있다.
- 경계 조건과 정보 부족 사례를 검증한다.
- 현재 융자 예시의 ‘지원금’을 융자한도·자금 사용계획 등으로 수정한다.

## 10. 7단계 — 지정양식 사업계획서 작성 [P0]

### 구현

- 공고에서 실제 사업계획서 제출 여부와 지정양식·버전을 확인한다.
- 확인된 기업정보·회사 자료·추가 답변을 문항과 평가 기준에 연결한다.
- 융자는 자금 사용·상환계획, 사업화는 목표·시장·추진계획 등 실제 공고 요구에 맞춰 작성한다.
- 근거 없는 실적·인증·수치·긍정적 평가를 생성하지 않는다. 누락은 `[추가 입력 필요]`로 표시한다.
- 사실, 향후 계획, 사용자 입력이 필요한 항목을 구분한다.
- 편집 가능한 HWPX/DOCX 출력 기능을 구현하고 원본 양식의 문항·표·페이지 설정·분량을 보존한다.
- 출력 지원 범위를 명시한다. 변환만으로 지정양식 준수가 보장된다고 표시하지 않는다.
- 양식 미확보 또는 미지원이면 그 상태를 안내하고 일반 초안을 지정양식 완성본처럼 제공하지 않는다.
- 출처 연결은 편집 화면에서 제공하고, 제출 문서에는 양식이 요구하지 않는 내부 검토 주석을 임의 삽입하지 않는다.
- 자동 저장, 수정 이력, 미리보기, 재생성 시 변경 비교와 사용자 수정 보존을 제공한다.

### 완료 기준

- 빈 입력에서 확인되지 않은 기업 설명이 생성되지 않는다.
- 대표 지정양식으로 생성한 파일을 열어 문항·표·잘림·분량을 검증한다.
- 편집·저장·재접속·다운로드가 일관되게 동작한다.
- 생성 실패 시 입력 및 기존 초안이 보존되고 재시도할 수 있다.

## 11. 8단계 — 증빙·AI 검토·신청 관리 [P1]

- 서류 체크리스트를 실제 파일과 연결하고 `미등록 / 검토 필요 / 준비 완료` 상태를 제공한다.
- 기업명·발급일·유효기간·조건부 제출 여부를 확인하되 불확실하면 검토 필요로 표시한다.
- 평가항목별 누락·근거 부족·예산 합계 오류·일정 불일치를 지적하고 수정 위치와 질문을 제공한다.
- 평가 점수를 합격 확률로 표현하지 않는다.
- 관심사업, 신규 맞춤 공고·마감·정정 알림과 수신 설정을 제공한다.
- 진행 상태는 `관심 / 자격 확인 / 서류 준비 / 초안 작성 / 제출 완료 / 결과 확인`으로 관리한다.
- 공식 신청 사이트로 연결한다. 사용자가 확인하지 않은 제출을 완료 상태로 바꾸지 않는다.

### 완료 기준

- 기업별 서류와 신청 상태가 분리된다.
- 알림 중복 발송과 수신 해제 처리를 검증한다.
- AI 검토의 지적 사항을 해당 문항·증빙에서 확인할 수 있다.

## 12. 9단계 — 프리미엄 SaaS UI [P2]

- 메뉴는 대시보드·지원사업·기업정보·사업계획서·서류함 중심으로 구성한다.
- 상단에 기업 전환·계정 메뉴를 제공한다.
- 공고 상세 상단은 사업명 → 지원 방식·한도·마감 → 우리 기업 자격 상태 → 주요 행동 순서로 정리한다.
- 데스크톱은 본문과 고정 요약 패널, 모바일은 하단 주요 버튼을 사용한다.
- 추천 카드에 추천 이유·확인 필요 조건·지역·마감·지원 방식을 표시한다.
- 지역·기관·업종·지원 방식·접수 상태 필터를 제공한다.
- 입력·미리보기 전환, 저장 상태, 보완 항목, 단계 이름과 실제 완료 상태를 표시한다.
- 모바일의 ‘왼쪽에 입력’ 같은 위치 의존 문구를 수정한다.
- 글자·여백·버튼·상태 색상 규칙을 통일하고 과도한 장식보다 가독성을 우선한다.
- 로딩·빈 결과·권한 오류·파일 분석 실패·재시도 화면을 제공한다.
- 키보드 접근, 입력 레이블, 오류 설명과 모바일 화면을 확인한다.
- 운영 빌드에서 개발 도구 표시를 제거한다.

## 13. 최종 검증과 인수 산출물

다음 핵심 시나리오를 실제 연결 또는 명확히 구분된 테스트 환경에서 검증한다.

1. 비회원 조회·추천 → 가입 → 기존 입력 이어받기.
2. 실제 등록증 OCR → 사용자 수정 → 저장 → 계획서 자동 입력.
3. 회사소개서·상품 URL → 근거 추출 → 확인 → 공고 문항에 반영.
4. 기업 전환과 다른 기업 자료 접근 차단.
5. 공고 수집 → 정정 감지 → 자격 판단 갱신.
6. 지정양식 생성 → 직접 편집 → 재접속 → 정상 파일 다운로드.
7. OCR·URL·첨부 분석·AI 생성 실패 후 복구.
8. 자료 삭제와 비회원 임시 파일 만료 처리.

최종 전달물:

- 구현된 코드와 필요한 데이터 변경.
- 실행·환경설정·외부 서비스 연결 방법.
- 지원하는 입력·출력 형식과 알려진 제한사항.
- 수집 출처 등록·재수집·검수 운영 방법.
- 단계별 검증 결과와 미완료 항목.

완료 기준은 화면에 버튼이 있는 것이 아니라, 실제 데이터와 파일을 통해 사용자 흐름이 끝까지 연결되는 것이다.
